# Together

Веб-комната для совместного просмотра видео. Один участник выбирает файл и управляет плеером, остальные подключаются по ссылке. В комнате до 8 человек, есть чат, микрофон и камера.

[Документация для разработчика](DEVELOPMENT.md) описывает модули проекта, протокол комнаты, хранилище, развёртывание, тесты и диагностику.

## Запуск с домашнего компьютера

Нужны Node.js 20+ и системные команды `ssh` и `ssh-keygen` для публичной ссылки. Для подготовки потокового видео нужны FFmpeg 6+ и FFprobe. На macOS с Homebrew их можно установить командой `brew install ffmpeg`. Зависимостей npm у проекта нет. На macOS можно открыть файл `Запустить Together.command`. Он запускает сервер с туннелем и открывает локальный адрес в браузере.

```bash
npm run share
```

1. Открой локальный адрес из терминала, обычно `http://127.0.0.1:3000`.
2. Введи имя, создай комнату и нажми **Выбрать видео**. Можно загрузить новый файл или выбрать сохранённый из библиотеки.
3. Когда в терминале появится публичный адрес, нажми **Пригласить друзей**. Друзьям достаточно открыть ссылку комнаты в браузере и ввести имя.

Together запускает SSH-туннель через tunnl.gg и выводит публичный адрес после проверки сайта. Адрес привязан к ключу проекта в `.data/`. При первом открытии браузер может показать страницу tunnl.gg с подтверждением перехода. Бесплатный туннель ограничен 5 ГБ трафика в сутки. Большие файлы загружай с локального адреса. Во время просмотра оставь Together включённым. `Ctrl+C` закрывает туннель и сайт. [Документация tunnl.gg](https://tunnl.gg/docs)

Для проверки на одном компьютере запусти `npm start` и открой `http://localhost:3000`. Второй участник может открыть ссылку комнаты в другом окне или профиле браузера.

## Видео и управление

- Загруженные файлы хранятся в `.data/videos/`, список — в `.data/library.json`. После смены фильма, закрытия комнаты или перезапуска файл доступен в библиотеке. Одинаковое содержимое сохраняется на диске один раз.
- С локального адреса на компьютере сервера ведущему доступна вся библиотека. При входе через внешний адрес ведущий видит видео, которые загружал из этого браузера на этом адресе. Остальные зрители видят выбранный для комнаты файл.
- Для исходного видео подходят MP4 (H.264 + AAC) и WebM. Если браузер не открывает оригинал, FFmpeg может подготовить совместимый HLS-поток. Сначала готовятся исходные сегменты, если кодеки подходят, и минимальное разрешение. Остальные варианты готовятся при выборе качества. Оригинал и готовые сегменты используются повторно.
- Участники подгружают видео вперёд и во время воспроизведения, и на паузе. HLS.js старается держать до двух минут буфера с учётом условий сети и ограничений браузера. Для оригинала предзагрузкой управляет браузер. Серая часть шкалы показывает загруженные участки, зелёная — просмотренную позицию.
- Запуск и перемотка во время просмотра ждут готовности подключённых участников. Для общего старта сервер назначает единый момент. Если у кого-то кончается буфер, комната ждёт и продолжает с общей позиции. Если браузер просит разрешить воспроизведение, нажми **Нажми, чтобы начать просмотр**.
- Ведущий управляет запуском, паузой, перемоткой и выбором файла. Роль можно передать через список **Ведущий** или корону на карточке. Громкость и качество у каждого свои. Пробел переключает паузу, стрелки перематывают на 10 секунд, если фокус вне полей и кнопок.
- Наведи курсор на шкалу, чтобы увидеть время до перемотки. В полном экране управление скрывается после короткой паузы. Наведи курсор к нижнему краю или коснись экрана, чтобы открыть его снова.

Фильм передаётся каждому зрителю с компьютера, на котором работает Together. На скорость влияют исходящий канал этого компьютера и пропускная способность туннеля. Ссылка даёт доступ в комнату любому, кому её переслали. Регистрация не нужна.

## Звонок и демонстрация экрана

Кнопки **Фильм** и **Звонок** переключают вид текущей комнаты. Каждый участник выбирает свой вид. Общий фильм, микрофон, камеры и показ экрана продолжают работать. В звонке можно показать всех или выбрать одну камеру или демонстрацию. Своя камера остаётся в углу, если выбран другой участник.

**Показать экран** открывает системный выбор вкладки, окна или монитора. Камера и микрофон работают одновременно с демонстрацией. Звук можно передать из другой вкладки, если браузер предлагает эту опцию. Кнопка **Заглушить звонок** выключает на твоём устройстве звук участников и демонстраций. Остановить показ можно в Together или через управление браузера.

## Микрофон и камера

Микрофон и камера используют WebRTC. Браузеру нужен HTTPS или локальный адрес. Обычно участники соединяются напрямую. В сетях, где прямое соединение не устанавливается, приложению нужен TURN. Можно передать список STUN/TURN через `ICE_SERVERS` или записать его в `.data/turn.json` как `{"iceServers":[...]}`. Для диагностики открой **Диагностика связи** в комнате.

**Записать тест микрофона** сохраняет четыре секунды звука в памяти браузера. Запись можно прослушать с выключенным микрофоном в звонке. Галочка **Обработка микрофона** управляет шумоподавлением и подавлением эха. Автоматическое усиление отключено.

## Прямой HTTPS без туннеля

Для прямого запуска нужен доступный из интернета публичный IP. На домашнем роутере направь TCP 80 и 443 на машину с Together. Если роутер получает непубличный адрес, входящие соединения требуют публичного адреса от провайдера или другого доступного сервера. Публичный IPv6 подходит, если он доступен всем зрителям.

1. Скопируй `.env.example` в `.env`.
2. Если есть домен или бесплатное DDNS-имя, направь его на этот IP и укажи имя в `DOMAIN`. Для запуска по публичному IP без домена задай `DOMAIN` равным IPv4 или IPv6 в квадратных скобках и добавь `CADDYFILE=Caddyfile.ip`.
3. Выполни `docker compose up -d --build` и открой HTTPS-адрес. Для IP Caddy запрашивает короткий сертификат Let's Encrypt и обновляет его автоматически. Кнопка **Пригласить друзей** копирует прямой HTTPS-адрес.

Видео лежат на диске машины с Together. Трафик идёт напрямую. Скорость и ограничения определяет интернет-подключение. Чтобы использовать собственный ретранслятор звонка, разверни Coturn на публичном IP, открой его порты и укажи параметры в `ICE_SERVERS`.

При отдельном HTTPS-прокси без Docker запусти `PUBLIC_URL=https://твой-адрес HOST=127.0.0.1 npm start`, направь прокси на локальный сервер и отключи буферизацию SSE. Запуск `npm run share` доступен, если входящее подключение сейчас невозможно.

Приложение читает `PORT` (3000), `HOST` (0.0.0.0 для `npm start`), `DATA_DIR` (`.data/`), `MAX_VIDEO_GB` (8), `ICE_SERVERS`, `PUBLIC_URL`.

## Проверки

```bash
npm run check
npm test
```

Тесты проверяют сохранение библиотеки, синхронизацию, управление комнатой, загрузку, HTTP Range, WebRTC-сигнализацию и HLS. Для тестов HLS нужны FFmpeg 6+ и FFprobe. [Лицензия HLS.js](HLS-LICENSE.txt).

## Диагностика

В папке `.data/logs/` сервер сохраняет ежедневный журнал JSON Lines (UTC). В него входят HTTP-запросы и обрывы, состояния комнат, события переподключения, изменения плеера и запуск или остановка туннеля. Токены, параметры URL, сообщения и видео в журнал не записываются.

В открытой комнате с видео запусти `node probe-stream.mjs` (на подготовленном Mac можно использовать `.data/bin/node`). Скрипт сравнит ICMP и HTTP-задержку, загрузку первых 4 МиБ файла и загрузку HLS-сегментов по локальному и публичному адресам. Опция `--interface en0` добавляет замер на Wi-Fi для публичного HTTP-клиента. SSH-соединение сервера продолжает идти по своему текущему маршруту.
