# Together

Небольшой сайт для совместного просмотра локальных видео с друзьями: общий плеер, комнаты по ссылке, текстовый чат, голос и вебки. Node.js 20+, без сторонних npm-зависимостей.

## Запуск

```bash
cd '/home/ilsur/Documents/ChatGPT/проекты/together'
npm start
```

Открой http://localhost:3000, введи имя, создай комнату и выбери видео. После полной загрузки файл доступен всем участникам комнаты. Кнопка «Пригласить друзей» копирует ссылку.

Для проверки на одном компьютере открой ссылку комнаты во второй вкладке. Первый участник — ведущий, он запускает, ставит на паузу и перематывает общий плеер. Корона на карточке другого участника передаёт ему управление. После выхода ведущего управление переходит следующему участнику. Громкость индивидуальная. Пробел — play/pause; стрелки — ±10 секунд, когда фокус вне полей ввода.

## Подключение друзей через интернет

`localhost` работает только на твоём компьютере. Для друзей нужен постоянно работающий сервер с внешним HTTPS-адресом. Этот проект использует Node.js и диск для больших файлов; статический хостинг и обычный Cloudflare Worker не заменяют его сервер.

Можно запустить на VPS с Node.js, проксируя HTTPS через Caddy. Пример Docker-развёртывания:

1. Привяжи домен к VPS, открой TCP 80/443.
2. Скопируй папку проекта на VPS с Docker Compose.
3. Создай рядом `.env` с `DOMAIN=watch.example.com` (укажи свой домен).
4. Выполни `docker compose up -d --build`.
5. Открой `https://твой-домен`, создай комнату и отправь друзьям её ссылку.

Не отдавай порт 3000 напрямую в интернет. Caddy автоматически получает сертификат для реального домена. Файлы фильма передаются через твой сервер: для трёх зрителей нужен исходящий канал примерно в три битрейта фильма. Учитывай место на диске и трафик VPS.

Камера и микрофон работают на HTTPS или localhost. В некоторых сетях прямой WebRTC не соединится: тогда нужен TURN. Укажи JSON-массив ICE-серверов в переменной `ICE_SERVERS` (STUN и собственный TURN). Без него используется публичный STUN Google, без гарантии соединения между любыми сетями. При публичном размещении используй временные TURN-учётные данные: конфигурация ICE выдаётся браузеру и не является секретной.

## Форматы и хранение

- Рекомендуется MP4 (H.264 + AAC) или WebM. MKV/MOV могут не воспроизводиться из-за кодеков; автоматического перекодирования нет.
- До 8 участников; голос и вебки соединяются напрямую между каждым участником. Лучше начинать с 2–4 человек, особенно при включённых камерах.
- Файлы до 8 ГБ по умолчанию, загружаются потоково на диск `.data/`, а не целиком в оперативную память.
- Ссылка — приглашение в комнату; любой обладатель ссылки может войти. Видео требует индивидуальной сессии участника. Регистрации и паролей нет.
- Комнаты, участники, сообщения и позиция сохраняются в `.data/rooms.json` с правами 0600. Вкладка хранит свой токен в sessionStorage и восстанавливает вход после обновления. Старый файл удаляется при замене; пустая комната с файлом — примерно через час. При перезапуске файлы и комнаты восстанавливаются.
- Для приватной компании друзей. Нет защиты от массового создания комнат или глобальной квоты на диск; перед широким публичным доступом добавь аутентификацию и квоты.

Переменные: `PORT` (3000), `HOST` (0.0.0.0), `DATA_DIR`, `MAX_VIDEO_GB` (8), `ICE_SERVERS`.

## Проверки

```bash
npm run check
npm test
```

Интеграционный тест проверяет создание комнаты, SSE, права ведущего, загрузку и HTTP Range (перемотку), команды синхронизации, чат, передачу ведущего, выход и блокировку запросов с чужого Origin. Проверка реальной связи через разные сети требует двух устройств и, при необходимости, TURN.

## Сегментное видео, качество и буфер

Для новых загрузок сервер использует FFmpeg/FFprobe (в Docker установлены автоматически). Оригинал доступен сразу после загрузки. В фоне последовательно создаются HLS/fMP4: копия H.264/AAC без перекодирования, если формат подходит, затем 360p, 480p, 720p и 1080p — только варианты не выше исходного разрешения. Обработка использует CPU и дополнительный диск на ноутбуке. Меню качества показывает подготовленные варианты; настройка индивидуальна для зрителя. В режиме «Авто» плеер выбирает между вариантами, доступными на момент открытия потока; новые варианты добавляются в меню по готовности.

В браузерах с Media Source Extensions HLS.js загружает сегменты на паузе до целевого запаса 120 секунд (с учётом ограничений памяти браузера). До подготовки сегментов оригинал использует обычный HTML-video и `preload=auto`: его объём предзагрузки определяет браузер. При отсутствии MSE используется нативный HLS, если он поддерживается браузером.

Буфер у каждого зрителя свой: запас вперёд от текущей позиции, преимущественно в памяти браузера. Это не то же самое, что файл фильма в `.data/` на сервере. Старт/возобновление ожидают до пяти секунд непрерывного буфера или весь оставшийся короткий конец видео. Верхняя серая часть единой шкалы показывает загруженные участки, зелёная — просмотренную позицию. В полном экране открывается весь плеер вместе с управлением. При ожидании друга указывается его имя и причина. Ведущий может продолжить без ожидания; при следующей перемотке обычная проверка готовности включается снова.

Файлы и комнаты восстанавливаются после перезапуска. На самой первой установке сохранения старые комнаты, существовавшие только в памяти прежней версии, восстановить нельзя. Папку `.data/` следует очищать вручную от оставшихся после перезапусков загрузок, когда они больше не нужны. HLS.js распространяется по Apache-2.0, см. `HLS-LICENSE.txt`.

В списке «Ведущий» текущий ведущий выбирает следующего участника. У назначенного ведущего одинаковые права независимо от того, кто создал комнату: общий play/pause, перемотка, загрузка/замена файла и передача роли дальше. При передаче просмотр ставится на общую паузу с сохранением позиции, а старые флаги буферизации сбрасываются. Громкость и качество загрузки остаются индивидуальными настройками каждого зрителя.

Обновление производительности: по умолчанию готовятся только исходные HLS-сегменты и самый низкий вариант (обычно 360p). Другие разрешения запускаются выбором в меню «по запросу», текущее качество остаётся до завершения обработки. Уже готовые варианты на диске используются повторно. Автоматический master-плейлист предпочитает перекодированные варианты до 720p и исключает тяжёлый исходник, когда есть облегчённый вариант; «Оригинал» доступен вручную. Автовыбор начинает с нижнего уровня и осторожно повышает качество. На Linux FFmpeg запускается с nice 15, используется preset superfast и ограничение максимального видеобитрейта для уменьшенных вариантов. Отображаемая Мбит/с — оценка HLS по загрузкам сегментов, а не измерение всей пропускной способности интернет-канала.
