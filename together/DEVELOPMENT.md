# Разработка Together

## Локальная среда

Рабочий каталог — `together/` внутри клона. Сервер использует стандартную библиотеку Node.js, браузерный клиент написан на JavaScript без сборки. HLS.js хранится в репозитории. Для запуска достаточно Node.js и системных утилит выбранного режима.

```bash
node --version
ffmpeg -version
ffprobe -version
HOST=127.0.0.1 npm start
```

Поддерживается Node.js 20+. Для полного тестового прогона нужны FFmpeg 6+ и FFprobe с поддержкой H.264, AAC и fMP4 HLS. На Linux очередь конвертации также использует `nice`. Открой `http://localhost:3000`, создай комнату и зайди по её ссылке из второго профиля. Данные эксперимента можно изолировать, указав отдельный `DATA_DIR` и свободный `PORT`.

Сервер загружает HTML, CSS и JS в память при старте, заранее считает ETag и gzip. После правок клиента перезапусти dev-сервер и обнови вкладки. Прежний `together-source.zip` содержит начальный снимок проекта. Актуальные исходники находятся в рабочем дереве.

Браузер получает сайт, фильм и события комнаты по HTTP(S). SSE доставляет состояние комнаты и сигнализацию, команды идут отдельными запросами. Микрофоны, камеры и демонстрации передаются между браузерами по WebRTC. Если выбран ICE-кандидат `relay`, этот трафик проходит через TURN. Звуковые дорожки воспроизводятся в браузере получателя.

## Комнаты и сессии

- Ссылка `/?room=<room>` содержит только ID комнаты и позволяет зайти под новым именем. Сервер выдаёт `{room,id,token}` отдельно каждому участнику, браузер сохраняет сессию в `sessionStorage`.
- Первая SSE-подписка переводит участника в состояние `present`. `online` показывает, открыт ли его SSE-поток. Heartbeat приходит каждые 4 секунды. После обрыва и после перезапуска сервер даёт сохранённым сессиям до 5 минут для возврата. При восстановлении сети и возвращении во вкладку клиент проверяет актуальность канала событий и при необходимости переподключает его.
- При 401 клиент восстанавливает страницу и пробует сохранённую сессию. Если повторный вход с токеном отклонён, клиент входит в ту же комнату как новый участник. 404 входа означает, что комната отсутствует.
- Ведущий выбирает файл, управляет воспроизведением и может передать роль. Передача роли и выход ведущего ставят фильм на паузу. При выходе ведущего роль получает первый оставшийся участник.
- В процессе допускается до 100 комнат и до 8 записей участников на комнату. Пустые комнаты старше часа удаляются периодической очисткой. При рестарте записи комнат старше суток пропускаются.

## Синхронизация фильма

Источник истины — `room.playback` на сервере. Поля `phase`, `position` в секундах, `at` в серверных миллисекундах и монотонный `sequence` задают общую шкалу. Для выбранного файла создаётся новая `video.version`. При смене файла комната ставится на паузу в начале, даже если тот же файл уже есть в библиотеке.

| Фаза | Поведение |
| --- | --- |
| `paused` | Позиция фиксирована. Перемотка ведущего сразу меняет её у всех. Браузеры могут продолжать предзагрузку. |
| `buffering` | Позиция фиксирована. Сервер ждёт готовности всех присутствующих участников перед стартом или возобновлением. Перемотка во время просмотра повторно проверяет буфер в новой точке. |
| `playing` | Цель клиента — `position + max(0, serverNow - at) / 1000`. Начало назначается на 650 мс вперёд. |

Клиент сверяет часы через `/api/time`, выбирая ответ с наименьшим RTT, и посылает отчёты `watch` по событиям плеера и каждые 1,5 секунды. Готовность требует паузы в пределах 0,4 с от цели и около 5 с буфера или остатка фильма. Отчёты по старому файлу или старому `sequence` не меняют состояние. Если событие плеера задержалось, ответ на `watch` возвращает более новое состояние.

Если у участника кончился буфер, браузер заблокировал воспроизведение или пропали отчёты, сервер возвращает всю группу в `buffering`. Остановка без команды ведущего тоже учитывается, если до конца фильма больше секунды. При разрыве SSE группа ждёт подключения. Если прервавшийся участник удалён по тайм-ауту во время ожидания, фильм остаётся на паузе до команды ведущего. Проверки порогов и переходов собраны в [playback.mjs](playback.mjs).

Команды ведущего в браузере отправляются последовательно. Серия быстрых перемоток учитывает последнюю запрошенную позицию. Клиент исправляет заметный дрейф перемещением к общей позиции. Громкость, качество, полноэкранный режим и вид звонка локальны для вкладки.

## Библиотека и доставка видео

1. Ведущий передаёт исходный файл телом запроса. Сервер проверяет размер и расширение, пишет поток в временный файл и по ходу считает SHA-256. После полной загрузки файл становится доступен под этим хешем. Одинаковые байты хранятся в библиотеке один раз.
2. `library.json` хранит индекс и имена, под которыми файл виден разным браузерам. Ведущий на loopback видит всю библиотеку. При внешнем входе список фильтруется по ключу браузера `X-Library-Key`. Ключ хранится в `localStorage` отдельно для каждого origin. Зрители читают выбранный для комнаты файл через свой токен.
3. Исходник отдаётся потоково с поддержкой одного HTTP Range. Через домен tunnl.gg один ответ 206 ограничен 16 МиБ. Повторный запрос может продолжить чтение с нужного смещения.
4. FFprobe определяет видеодорожку и длительность. У совместимого H.264/AAC-файла FFmpeg готовит HLS без перекодирования. Также готовится самый лёгкий вариант. Высоты 360, 480, 720 и 1080 используются, если позволяют размеры исходника. Остальные доступные варианты готовятся по запросу. Очередь общая для процесса, результат переиспользуется по пути исходника.
5. HLS отдаётся в fMP4 с целевой длительностью сегмента 4 секунды. Вариант появляется в выдаче после проверки готового VOD-плейлиста и сегментов. Режим `Авто` предпочитает готовые перекодированные варианты до 720p. Браузер использует HLS.js при поддержке MSE или встроенный HLS. При недоступности потока остаётся оригинал, если браузер поддерживает его кодеки. Поздняя готовность нового варианта сама по себе не сбрасывает успешно запущенный просмотр.

Поддерживаемые расширения заданы в [video-library.mjs](video-library.mjs). Для прямого воспроизведения проще всего проверить MP4 с H.264 и AAC. HLS.js нацелен на буфер до 120 секунд при лимите буфера 96 МиБ. Для оригинала буфером управляет браузер. Каждый зритель загружает фильм с сервера, поэтому требуемая исходящая скорость растёт с числом зрителей.

## HTTP API и события

Публичные маршруты доступны без токена участника. Сессия выдаётся в ответе `{room,id,token}`. Имена ограничиваются 32 символами.

| Метод и путь | Назначение |
| --- | --- |
| `GET /api/time` | `{now}` для синхронизации часов и проверки доступности |
| `GET /api/address` | `{url,sharing}`. В режиме туннеля `url` появляется после успешной проверки |
| `GET /api/config` | `iceServers`, `maxBytes`, `maxMembers`, флаги `relayConfigured` и при ошибке `relayError` |
| `POST /api/rooms` | Создание комнаты и сессии ведущего из `{name}` |
| `POST /api/rooms/<room>/join` | Вход с `{name}` или восстановление по `{token}` |

Остальные маршруты имеют префикс `/api/rooms/<room>/`. Сервер принимает `Authorization: Bearer <token>` или параметр `token`, когда браузерный API не позволяет добавить заголовок. Изменяющие запросы принимают JSON, кроме `upload`.

| Метод и суффикс | Данные и результат |
| --- | --- |
| `GET events` | Поток `text/event-stream` для текущего участника |
| `HEAD session` | 204, если сессия ещё действительна |
| `POST leave` | Выход участника |
| `POST clientevent` | `{reason}`. Журналирует известные причины переподключения клиента |
| `POST chat` | `{text}`. Сообщение до 1000 символов, в комнате хранится до 80 последних |
| `POST signal` | `{to,signal}`. Пересылает WebRTC-сигнал адресату в комнате |
| `POST host` | `{id}`. Передача роли участнику по его ID |
| `POST playback` | `{action,version,position?,sequence?}`. Действия `play`, `pause`, `seek`, `ended` |
| `POST watch` | `{version,sequence,position,duration,bufferAhead,waiting,blocked,paused}`. Отчёт плеера для общей синхронизации |
| `GET library` | `{videos}` с доступными ведущему файлами. Для внешнего доступа учитывается `X-Library-Key` |
| `POST select` | `{id}`. Выбор файла из библиотеки с теми же правилами доступа |
| `POST upload` | Файл в теле запроса, обязательны `Content-Length` и URL-кодированное имя в `X-File-Name`. Успех меняет фильм в комнате |
| `GET media?quality=<id>` | Каталог HLS-вариантов, версия файла, длительность, ревизия и статусы. `quality` можно опустить |
| `GET/HEAD video?v=<version>` | Исходник или 206 для корректного `Range`, 416 для недопустимого диапазона |
| `GET hls/<version>/master.m3u8` | Плейлист готовых вариантов, 409 если варианты ещё готовятся |
| `GET/HEAD hls/<version>/<quality>/<file>` | Плейлист варианта, `init.mp4` или `part-000000.m4s` и последующие сегменты |

Операции `host`, `playback`, `library`, `select` и `upload` требуют роли ведущего. Ответы с ошибками обычно содержат `{error}`. 401 означает недействительный токен, 403 — недостаточно прав или чужой `Origin`, 404 — ресурс или версия отсутствует, 409 — конфликт с состоянием комнаты.

### События SSE

| Событие | Содержимое |
| --- | --- |
| `state` | Полный снимок комнаты с ведущим, участниками, фильмом, плеером и чатом |
| `heartbeat` | `null`, подтверждение открытого соединения |
| `playback` | Новое состояние плеера с `version` |

| `chat` | Сообщение чата |
| `signal` | `{from,signal}` для одного адресата |

## Звонки

На каждую пару участников создаётся один `RTCPeerConnection`. Инициатор выбирается по ID. При согласовании для микрофона, камеры, экрана и звука экрана выделяется по отдельному слоту. Камера и микрофон могут работать параллельно с демонстрацией. Пользователь выбирает передачу звука перед запуском показа. `getDisplayMedia()` запрашивает `restrictOwnAudio` для исключения аудио Together, `windowAudio: 'window'` для выбранного окна и `systemAudio: 'include'` для монитора. Для окон и мониторов клиент проверяет применение `restrictOwnAudio` на полученной дорожке до её передачи. Текущая вкладка Together исключена из выбора. Доступность захвата зависит от браузера и ОС. [Параметры захвата экрана](https://www.w3.org/TR/screen-capture/).

Входящие сигналы обрабатываются последовательно. ICE-кандидаты, полученные до SDP, ждут установки удалённого описания. События WebRTC, смена дорожек и переключение вида звонка не меняют серверный таймлайн фильма.

Камеры в режиме фильма расположены в боковой колонке. В полном экране те же карточки переходят в ленту плеера. Дополнительно `documentPictureInPicture.requestWindow()` открывает общее окно камер поверх других приложений по нажатию кнопки. Миниатюры используют исходные видеодорожки без захвата новых устройств. Закрытие по `contextmenu` или `pagehide` освобождает ссылки на миниатюры. При выходе из комнаты окно закрывается. Положение и изменение размера контролирует браузер.

Захват микрофона использует флаги шумоподавления и подавления эха из интерфейса, автоматическое усиление выключено. Локальный тест записывает четыре секунды через `MediaRecorder` и воспроизводит результат из Blob. При включённом микрофоне тест слушает копию текущей дорожки. При выключенном он открывает микрофон только для записи и завершает захват.

### STUN и TURN

Браузеру нужны разрешения на устройства и безопасный контекст (HTTPS или localhost). Ссылка HTTPS обеспечивает доступ к сайту и сигнализации. Для связи из разных сетей RTC сначала использует ICE, а TURN предоставляет ретрансляцию, если прямой маршрут недоступен.

Приоритет настроек — `ICE_SERVERS`, затем `iceServers` в `DATA_DIR/turn.json`, затем параметры `meteredDomain` и `apiKey` из этого файла. В последнем случае сервер получает временные параметры ICE у Metered и кеширует ответ на 5 минут. При отсутствии конфигурации и при ошибке сервер возвращает встроенный список STUN. Наличие `relayConfigured` само по себе не доказывает доступность TURN. Рабочий маршрут проверяется по выбранной паре ICE в отчёте звонка.

```json
{
  "iceServers": [
    { "urls": "stun:stun.l.google.com:19302" },
    {
      "urls": ["turn:turn.example.com:3478?transport=udp", "turns:turn.example.com:5349?transport=tcp"],
      "username": "<turn-username>",
      "credential": "<turn-credential>"
    }
  ]
}
```

`/api/config` отдаёт ICE-параметры браузерам без сессии комнаты. Для внешнего размещения используй короткоживущие учётные данные TURN там, где их выдаёт провайдер. Ключ API для получения учётных данных хранится на сервере в `turn.json`.

## Запуск и размещение

| Параметр | Значение и область действия |
| --- | --- |
| `HOST` | Интерфейс для `npm start`, по умолчанию `0.0.0.0`. `npm run share` слушает `127.0.0.1` |
| `PORT` | HTTP-порт, по умолчанию 3000 |
| `DATA_DIR` | Каталог состояния, по умолчанию `.data/` рядом с сервером |
| `MAX_VIDEO_GB` | Лимит файла, по умолчанию 8 ГиБ |
| `PUBLIC_URL` | Публичный origin для `npm start`, например `https://watch.example.com` |
| `ICE_SERVERS` | JSON-массив STUN/TURN для `RTCPeerConnection` |
| `DOMAIN` | Публичный домен или IP для Compose и Caddy |
| `CADDYFILE` | Конфигурация Caddy для Compose, по умолчанию `Caddyfile`. Для развёртывания по IP предусмотрен `Caddyfile.ip` |

Скопируй [`.env.example`](.env.example) в `.env` для Compose. При обычном запуске через Node переменные задаются в окружении. `compose.yaml` монтирует весь каталог данных приложения в именованный том `videos`. `caddy_data` и `caddy_config` хранят состояние HTTPS-прокси.

- **Локально.** `npm start` для разработки или отдельного HTTPS-прокси. Прокси должен пропускать SSE без буферизации и поддерживать HTTP Range. Node-приложение за отдельным прокси можно привязать к loopback.
- **Из домашней сети.** `npm run share` или файл запуска на macOS. SSH-ключ в каталоге данных задаёт стабильное имя туннеля. Лаунчер проверяет `/api/time` по внешнему адресу, публикует его только после успешного ответа и переподключает SSH после сбоя. Для HTTP 429 проверка замедляется. Трафик фильмов учитывается в квоте провайдера. [Лимиты и правила tunnl.gg](https://tunnl.gg/docs#limits).
- **Прямой HTTPS.** Заполни `.env`, направь TCP 80 и 443 на хост с Caddy и выполни `docker compose up -d --build`. Для сервера за домашним роутером нужен входящий маршрут с интернета. При CGNAT нужен публичный адрес от провайдера или размещение на доступном извне сервере. Настрой TURN отдельно от HTTP-прокси. Шаги для домена и публичного IP есть в [руководстве по запуску](README.md#прямой-https-без-туннеля).

Приложение хранит живые комнаты, подключения SSE и очередь FFmpeg в одном процессе. Используй один экземпляр на каталог данных. Для нескольких экземпляров понадобится общее хранилище состояния и координация событий, загрузок и обработки видео.

| Файл в `DATA_DIR` | Содержимое |
| --- | --- |
| `library.json` и `videos/*.video` | Индекс библиотеки и оригиналы. Старые мигрированные оригиналы могут лежать непосредственно в `DATA_DIR` |
| `*.video.hls/` рядом с оригиналом | Восстанавливаемые HLS-плейлисты и сегменты |
| `rooms.json` | Снимок комнат, участники с токенами, позиция фильма и история чата. Плеер после рестарта возвращается на сохранённую позицию в паузе |
| `turn.json` | Частная конфигурация TURN или ключ поставщика |
| `tunnel_ed25519`, `tunnel_ed25519.pub`, `ssh_known_hosts` | Ключ туннеля и доверенные хосты SSH |
| `logs/YYYY-MM-DD.jsonl` | Серверный журнал по UTC |

Для согласованной копии останови сервис и скопируй каталог данных или том. Для сохранения прежнего стабильного адреса перенеси ключ туннеля вместе с каталогом. Оригиналы нужны для восстановления библиотеки, готовый HLS можно построить заново. Приложение не удаляет старые оригиналы и логи автоматически. Храни рабочие `.env`, `.data/`, токены, логи и пользовательские видео вне Git.

## Диагностика

```bash
curl -fsS http://127.0.0.1:3000/api/time
curl -fsS http://127.0.0.1:3000/api/address
curl -fsS https://watch.example.com/api/time
```

| Симптом | Где проверять |
| --- | --- |
| Публичный адрес отдаёт `Not Found`, 502 или 503 | Сравни локальный и внешний `/api/time`, затем `/api/address`. Если локальный ответ есть, смотри `tunnel_closed`, `tunnel_connected`, `tunnel_health_failed` или логи HTTPS-прокси. Когда адрес снова работает, проверь полное приглашение `/?room=…`. |
| `EADDRINUSE` | Узнай, какой процесс слушает порт. Лаунчер переиспользует уже запущенный Together. Для отдельного dev-сервера задай другой `PORT`. |
| Участник вылетел или получил 401 | Сверь `events_disconnected`, `client_reconnected` и `member_left`. Удалённая по тайм-ауту сессия требует повторного входа. |
| Видео медленно грузится | В комнате с фильмом запусти `node probe-stream.mjs`. Скрипт сравнит ICMP, HTTP RTT, время до первого байта, диапазон исходника до 4 МиБ и готовые HLS-сегменты. Если локально быстро, а извне медленно, проверь исходящий канал и туннель. Если медленно и локально, проверь диск, загрузку CPU и очередь FFmpeg. |
| Плеер ждёт после перемотки | Сверь `version`, `sequence`, `phase`, актуальность `watch`, буфер и разрешение автовоспроизведения каждого зрителя. |
| Камера есть, звук пропадает или пищит | Сравни локальную запись микрофона со звуком звонка. Сними **Диагностику связи** с принимающей стороны при сбое. Смотри выбранную ICE-пару, счётчики входящего RTP, потери, jitter и `concealedSamples`. |

У замера есть параметры `--local`, `--public`, `--room` и `--interface`. `--interface en0` привязывает только публичные HTTP-запросы утилиты к интерфейсу. Путь SSH-туннеля и настройки VPN она не меняет. В журнале запросов есть путь, статус, время и объявленный размер ответа. Строка запроса, токены и содержимое сообщений в эти записи не попадают. Для анализа обрыва сравни журнал клиента с `http_interrupted` и событиями комнаты по времени UTC.

## Проверки перед изменениями

```bash
npm run check
npm test
```

Без npm те же команды запускаются через `node --check server.mjs`, `node --check share.mjs`, `node --check public/app.js` и `node --test test/*.test.mjs`. Автотесты покрывают API, доступ по ролям, возобновление сессии, библиотеку, Range, HLS, буферизацию, перемотку и сигнализацию. Тестам загрузки и HLS нужен доступ к локальному HTTP-порту и временным каталогам.

Для правок плеера открой два независимых профиля. Проверь паузу и перемотку в обе стороны, задержи загрузку сегментов у зрителя и убедись, что ждёт вся комната. Восстанови сеть и проверь общий старт из той же позиции. Проверь смену ведущего, повторный выбор файла после рестарта и управление в полном экране.

Для правок звонка проверь два браузера в разных сетях, камеру и звук в обе стороны, локальную запись, показ вкладки и переключение между фильмом и звонком. Прямой маршрут и TURN проверяй отдельно. Автотесты сигнализации не измеряют качество звука на реальных устройствах.

Для Android проверь публичное приглашение в мобильном Chrome, доступ к камере и микрофону, ручное разрешение звука, приём демонстрации с компьютера и возврат во вкладку после смены сети. Раскладку проверяй на ширинах 320–600 CSS-пикселей и после поворота экрана. При отсутствии `getDisplayMedia` или Document Picture-in-Picture клиент скрывает соответствующее управление отправкой и отдельным окном. Приём медиа использует общий WebRTC-код.
